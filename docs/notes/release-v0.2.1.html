🚀 EventRunner7 - Release v0.2.1

What's new in v0.2.1?

This release is mostly about understanding what your rules are doing: errors that actually tell you what's wrong, a rule status view right in the app, and friendlier syntax.

Errors that tell you what's wrong

When a rule fails now, the log names the problem, points at the position, and suggests the fix:
  • Variable 'temperatur' is not defined — misspelled, or forgot to define it? (er.triggerVars.temperatur, er.defglobals.temperatur, or a rule assignment)
  • Head function 'fnt' is not allowed in a rule condition — did you mean 'fmt'?
  • post() posts events; move it into the action
  • no such property 'valu' — did you mean 'value'?
All errors — syntax, registration, and runtime — now use the same shape: message, line and column, and a caret under the problem. throw('...') also actually works now (it silently didn't before).

Rule status in the app UI

The EventRunner7 device now has a 🔄 Rules button. Press it to see every rule in the app: ✅ running, ❌ disabled, the last error, and what each rule listens to: RULE1 entry-light ✅ ⚡ door:breached → device 42 RULE2 ❌ disabled ❌ Variable 'temperatur' is not defined … at line 1, col 24 The view also updates on its own when a rule errors or completes.

Friendlier syntax

  • when … then … — rules can read like English:
rule("when door:breached then light:on") rule("when motion:breached since 2min then alarm:on")
  • Duration literals — 5s, 30sec, 5min, 2h, 1d instead of clock formats:
rule("button:pressed debounce 30s => log('settled')")
  • 'when' is not reserved — it still works as a variable name.

Trigger lists in your own words

Registration logs and info() now quote the expression you wrote next to what it resolved to: ⚡ doorSensor:breached → device 42 ⚡ myLamps:isOn → devices 55, 56, 57 🕒 @23:00 → 23:00:00

Examples to learn from

Three runnable example projects in the examples/ folder — motion lights, a morning routine, and a door alert, including one deliberately broken rule so you can see the new error format in action. They run offline in flua with simulated devices; nothing touches your real controller.

Fixes

  • List checks like switches:allTrue and temps:average silently always saw "on" — fixed.
  • Internal cleanups: faster rule compilation, a stricter test suite that caught several long-hidden test bugs.

If you are updating

Nothing should break — everything above is additive, and the new error messages are more talkative than before. If a rule now fails at registration, it was already silently broken; the message tells you why.
